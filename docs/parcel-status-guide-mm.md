## အခြေအနေစနစ် အကြောင်း

Real flow —

```
[မဲဆောက်ရုံး]
ဖောက်သည် ပစ္စည်းယူလာ → မဲဆောက်တွင် Register လုပ်ပြီး Tracking Number ထုတ်ပေး
      │
      ▼  (နယ်စပ်ဖြတ်ကူးသည်)
[မြဝတီရုံး]
ပါဆယ်ရောက် → RECEIVED_AT_MYAWADDY သတ်မှတ် → VERIFIED → ပို့ဆောင်ရေး ...
```

ထို့ကြောင့် ပါဆယ်တစ်ခုသည် **မဲဆောက်ဘက်တွင် ဦးစွာ Register ဖြစ်ပြီးသား**
ဖြစ်သည်။ `RECEIVED_AT_MYAWADDY` ဆိုသည်မှာ Register အသစ်လုပ်ခြင်းမဟုတ်ဘဲ
**မြဝတီရုံးသို့ ရုပ်ဝတ္ထုအားဖြင့် ရောက်ရှိကြောင်း အတည်ပြုခြင်း**သာဖြစ်သည်။

ပါဆယ်သည် `RECEIVED_AT_MYAWADDY` မှ နောက်ဆုံးဦးတည်ချက်သို့
**အဆင့် ၁၁ ဆင့်** ဖြတ်သန်းပါသည်။
ဝန်ထမ်းများ၊ မန်နေဂျာများနှင့် စာရင်းကိုင်များသည် ပါဆယ်၏ အခြေအနေကို
အချိန်မှန်စစ်ဆေးနိုင်သည်။

## အခြေအနေ အစီအစဉ် ဇယား

```
မဲဆောက်မှ လက်ခံ
      │
      ▼
RECEIVED_AT_MYAWADDY ──────────────────────────► DAMAGED
(မြဝတီရောက်ရှိ)                                  (ပျက်စီးနေ)
      │
      ▼
  VERIFIED ──────────────────────────────────── MISSING
(စစ်ဆေးပြီး)                                     (ဆုံးရှုံး)
      │
      ▼
READY_FOR_DELIVERY
(ပို့ဆောင်ရန် အဆင်သင့်)
      │
      ▼
  ASSIGNED ◄──────────────────────────────────────┐
(သတ်မှတ်ပေးပြီး)                                  │
      │                                            │
      ▼                                            │
OUT_FOR_DELIVERY                                   │
(ပို့ဆောင်နေဆဲ)                                    │
      │                                            │
   ┌──┴──┐                                         │
   ▼     ▼                                         │
DELIVERED  DELIVERY_FAILED ──► RETURN_TO_OFFICE ───┘
(ပို့ပြီး)  (မပို့ရနိုင်)     (ရုံးသို့ပြန်)
                  │
                  ▼
          RETURNED_TO_SENDER
          (ပေးပို့သူထံ ပြန်)
```

> **Terminal Statuses** — `DELIVERED`, `RETURNED_TO_SENDER`, `DAMAGED`, `MISSING`
> ဤအဆင့်ရောက်ပြီးသောပါဆယ်ကို နောက်ထပ် မပြောင်းနိုင်တော့ပါ။

## အခြေအနေ တစ်ခုချင်း ရှင်းလင်းချက်

---

### 1. `RECEIVED_AT_MYAWADDY` — မြဝတီရုံးသို့ ရောက်ရှိကြောင်း အတည်ပြုပြီး

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | မဲဆောက်တွင် Register ပြီးသားပါဆယ် မြဝတီရုံးသို့ **ကိုယ်ထည်အားဖြင့် ရောက်ရှိလာကြောင်း** မြဝတီဘက်မှ အတည်ပြုသောအဆင့် |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ သို့မဟုတ် Admin |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `VERIFIED`, `DAMAGED`, `MISSING` |
| **မှတ်ချက်** | Register မဲဆောက်တွင် ပြီးနှင့်သည်။ ဤအဆင့်သည် **နယ်စပ်ဖြတ်ကူးပြီး မြဝတီရောက်ကြောင်း** စစ်ဆေးအတည်ပြုရုံသာဖြစ်သည် |

**ဤအဆင့်တွင် ဆောင်ရွက်ရမည့်အချက် —**
> မဲဆောက်မှ ပါဆယ် မြဝတီရုံးသို့ ရောက်လာသောအခါ မန်နေဂျာသည်
> Tracking Number ဖြင့် ရှာဖွေ၍ `RECEIVED_AT_MYAWADDY` သို့ Status ပြောင်းကာ
> ရောက်ရှိကြောင်း အတည်ပြုပါ။ Register ဆိုင်ရာ အချက်အလက်များ မဲဆောက်ဘက်က ထည့်ပြီးသား ဖြစ်သည်။

---

### 2. `VERIFIED` — စစ်ဆေးပြီး

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်၏ အချက်အလက်များနှင့် ပါဆယ်ကိုယ်တိုင်ကို စစ်ဆေးပြီးသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ သို့မဟုတ် Admin |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `READY_FOR_DELIVERY`, `DAMAGED`, `MISSING` |
| **မှတ်ချက်** | ပါဆယ် အကြောင်းအရာ ပြဿနာ မရှိကြောင်း အတည်ပြုသောအဆင့် |

**ဤအဆင့်တွင် ဆောင်ရွက်ရမည့်အချက် —**
> ပါဆယ်ကို ကိုယ်တိုင်စစ်ဆေး၍ ရောက်ရှိမှန်ကန်ကြောင်း သေချာသောအခါ
> အခြေအနေကို `VERIFIED` သို့ ပြောင်းပါ။

---

### 3. `READY_FOR_DELIVERY` — ပို့ဆောင်ရန် အဆင်သင့်

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်ကို ပို့ဆောင်ရေးဝန်ထမ်းသို့ သတ်မှတ်ပေးရန် အဆင်သင့်ဖြစ်နေသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `ASSIGNED` |
| **မှတ်ချက်** | ဤအဆင့်ရောက်မှသာ ဝန်ထမ်းထံ သတ်မှတ်ပေးနိုင်သည် |

---

### 4. `ASSIGNED` — သတ်မှတ်ပေးပြီး

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်ကို ပို့ဆောင်ရေးဝန်ထမ်းတစ်ဦးထံ သတ်မှတ်ပေးပြီးသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `OUT_FOR_DELIVERY`, `READY_FOR_DELIVERY` (ပြန်သိမ်း) |
| **မှတ်ချက်** | ဝန်ထမ်းသည် "ကျွန်ုပ်၏ Assignment များ" တွင် ဤပါဆယ်ကို တွေ့မည် |

**ဤအဆင့်တွင် ဆောင်ရွက်ရမည့်အချက် —**
> မန်နေဂျာသည် ပါဆယ် Detail ထဲမှ "သတ်မှတ်ပေး" ကို နှိပ်၍ ဝန်ထမ်းအမည် ရွေးပါ။
> တစ်ကြိမ်တည်း ဝန်ထမ်းတစ်ဦးသာ သတ်မှတ်နိုင်သည်။

---

### 5. `OUT_FOR_DELIVERY` — ပို့ဆောင်နေဆဲ

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ဝန်ထမ်းသည် ပါဆယ်ကိုင်ဆောင်၍ လက်ခံသူထံ ထွက်သွားသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | ပို့ဆောင်ရေးဝန်ထမ်း |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `DELIVERED`, `DELIVERY_FAILED` |
| **မှတ်ချက်** | ဝန်ထမ်း App မှ "ထွက်ပြီ" ကို နှိပ်သောအခါ ဤအဆင့်သို့ ရောက်သည် |

---

### 6. `DELIVERED` — ပို့ဆောင်ပြီးစီး ✅

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်ကို လက်ခံသူထံ အောင်မြင်စွာ လက်ဆင့်ကမ်းပြီးသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | ပို့ဆောင်ရေးဝန်ထမ်း |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | **မရှိ** — Terminal Status |
| **မှတ်ချက်** | ဤအဆင့်ရောက်သောအခါ ပို့ဆောင်ခနှင့် COD ငွေကို မှတ်တမ်းတင်သည်။ Payment Record ဖွဲ့သည် |

**ဤအဆင့်တွင် ဆောင်ရွက်ရမည့်အချက် —**
> ဝန်ထမ်းသည် — လက်ခံသူ၏ နာမည်ကို အတည်ပြု၊ ကောက်ခံသော ငွေပမာဏ ဖြည့်ပြီး
> "DELIVERED" ကို နှိပ်၍ သိမ်းဆည်းရမည်။

---

### 7. `DELIVERY_FAILED` — ပို့ဆောင်မအောင်မြင် ❌

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ဝန်ထမ်းသည် သွားပေမယ့် ပါဆယ်လက်ဆင့်ကမ်းမရသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | ပို့ဆောင်ရေးဝန်ထမ်း |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `RETURN_TO_OFFICE`, `ASSIGNED` (ထပ်သတ်မှတ်), `RETURNED_TO_SENDER` |
| **မှတ်ချက်** | မအောင်မြင်ရသောအကြောင်းရင်းကို မှတ်တမ်းတင်ရမည် |

---

### 8. `RETURN_TO_OFFICE` — ရုံးသို့ ပြန်ရောက်

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | မပို့ရနိုင်သော ပါဆယ်ကို ဝန်ထမ်းသည် မြဝတီရုံးသို့ ပြန်ယူလာသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | `ASSIGNED` (ထပ်ပို့ရန်), `RETURNED_TO_SENDER` (မဲဆောက်ပြန်), `READY_FOR_DELIVERY` |
| **မှတ်ချက်** | ပါဆယ်ကို ဘာဆက်လုပ်မည်ကို ဆုံးဖြတ်ရသောအဆင့် |

---

### 9. `RETURNED_TO_SENDER` — ပေးပို့သူထံ ပြန်ပို့ပြီး

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်ကို မဲဆောက်ဘက် ပေးပို့သူထံ ပြန်ပို့ပြီးသောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ သို့မဟုတ် Admin |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | **မရှိ** — Terminal Status |
| **မှတ်ချက်** | ပေးပို့သူကို ပါဆယ်ပြန်ရသွားပြီ — ငွေတောင်းဆိုမှု ဖြစ်နိုင်သည် |

---

### 10. `DAMAGED` — ပါဆယ် ပျက်စီး ⚠️

| အချက် | အသေးစိတ် |
|--------|-----------|
| **အဓိပ္ပာယ်** | ပါဆယ်သည် ပျက်စီးနေသောကြောင့် ပုံမှန်လမ်းကြောင်းဖြင့် မပို့နိုင်သောအခြေအနေ |
| **မည်သူ လုပ်သနည်း** | မန်နေဂျာ သို့မဟုတ် Admin |
| **နောက်ထပ် ဖြစ်မည့်အခြေ** | **မရှိ** — Terminal Status |
| **မှတ်ချက်** | `RECEIVED_AT_MYAWADDY` သို့မဟုတ် `VERIFIED` အဆင့်မှ ပြောင်းနိုင်သည်။ ပျက်စီးမှု အကြောင်းရင်း မှတ်တမ်းတင်ရမည် |

---

### 11. `MISSING` — ပါဆယ် ပျောက်ဆုံးနေ 🔴

| အချက် | အသေးစိတ် |
